# score-springboot スキル

SpringBoot3 Webアプリケーションと設計書を **100点満点で客観的に採点する** スキルです。
4つのサブエージェントが役割分担して並列採点し、再現可能なスコアを生成します。

---

## 使い方

```
/score-springboot [アプリフォルダパス]
```

引数を省略した場合は、**カレントフォルダ**を採点対象として使用します。

**例:**
```
/score-springboot C:/work/full-auto-dev/demo16
/score-springboot
```

---

## 採点構成（合計100点）

| カテゴリ | 配点 | 担当エージェント | 評価対象 |
|--------|-----|--------------|---------|
| 要件定義品質 | 15点 | RequirementsEvaluator | `docs/requirements/` |
| 設計品質 | 20点 | DesignEvaluator | `docs/design-basic/`, `docs/design-detail/` |
| 実装品質 | 40点 | ImplementationEvaluator | `src/main/java/`, `pom.xml` |
| テスト品質 | 25点 | TestEvaluator | `src/test/java/`, `e2e/tests/` |

---

## 評価ランク

| スコア | ランク | 意味 |
|------|------|------|
| 90〜100点 | S | 卓越 — 模範的な品質、全項目で高水準 |
| 80〜89点 | A | 優秀 — 軽微な改善余地あり |
| 70〜79点 | B | 良好 — いくつかの改善課題あり |
| 60〜69点 | C | 合格 — 複数の重要課題あり |
| 50〜59点 | D | 要改善 — 大幅な改善が必要 |
| 0〜49点 | F | 不合格 — 根本的な見直しが必要 |

## 採点基準の詳細

### 1. 要件定義品質（15点）

| 項目 | 配点 | 満点の条件 |
|-----|-----|---------|
| A. 機能要件の定義品質 | 6点 | 要件IDあり・受け入れ条件あり・**異常系記載あり**・権限差異定義あり（全て必須） |
| B. 非機能要件の定義品質 | 5点 | パフォーマンス・セキュリティ・ユーザビリティが**数値目標付き**で定義 |
| C. トレーサビリティと構造 | 4点 | 要件ID↔画面↔テストの対応表・権限マトリクス・優先度が全てある |

### 2. 設計品質（20点）

| 項目 | 配点 | 満点の条件 |
|-----|-----|---------|
| D. アーキテクチャ・基本設計 | 6点 | 3層構造図・DB定義（制約・インデックス含む）・**排他制御設計**が全てある |
| E. API・画面設計 | 5点 | 全エンドポイントの定義・**エラーレスポンス設計**・認証要否が全てある |
| F. クラス・詳細設計 | 5点 | 全主要クラスのメソッドシグネチャ・バリデーション定義・**シーケンス図**が全てある |
| G. 一般Webアプリ要件への対応 | 4点 | セキュリティ設計・ログ設計・エラー処理設計・環境設定管理が全て設計書に記述 |

### 3. 実装品質（40点）

| 項目 | 配点 | 満点の条件 |
|-----|-----|---------|
| H-1. レイヤー分離 | 3点 | Controller/Service/Repositoryの責務混在が**0件**（具体的に確認） |
| H-2. 依存性注入 | 2点 | `@Autowired` フィールドインジェクションが**0件** |
| H-3. 例外処理の一貫性 | 3点 | GlobalExceptionHandler + カスタム例外 + Ajax/HTML両対応 + 適切なHTTPステータス |
| I-1. 認証・認可 | 4点 | FormLogin + URLロールベース制御 + セッションタイムアウト設定 |
| I-2. パスワード・機密情報管理 | 3点 | BCrypt + ソースにシークレット**なし** + ログに機密情報**なし** |
| I-3. バリデーション・XSS/SQLi対策 | 3点 | **全フォーム**にサーバーサイドバリデーション + Thymeleaf/MyBatisの安全使用 |
| I-4. CSRF対策 | 2点 | CSRF保護が有効（`.csrf().disable()` は**0点**） |
| J-1. ログ実装 | 3点 | SLF4J使用 + エラーログ + **操作ログ（監査ログ）** |
| J-2. 命名・コード可読性 | 2点 | 命名規則統一 + マジックナンバーが定数化 |
| J-3. DRY原則 | 3点 | 重複コード**0件** |
| K-1. トランザクション管理 | 2点 | `@Transactional` + `readOnly=true` の使い分け |
| K-2. ページネーション | 2点 | 全一覧画面でページネーション（全件取得なし） |
| K-3. 楽観的ロック/排他制御 | 2点 | 競合が発生し得る**全更新操作**に実装 |
| K-4. 環境設定管理 | 2点 | 開発/本番環境の設定切り替えが可能な構造 |
| L-1. 機能要件の実装率 | 2点 | 全機能要件100%実装 |
| L-2. 設計書との実装一致度 | 2点 | クラス名・メソッド名・エンドポイントが設計書と一致 |

### 4. テスト品質（25点）

| 項目 | 配点 | 満点の条件 |
|-----|-----|---------|
| M-1. 単体テスト網羅性 | 4点 | 全主要クラスの90%以上にテストあり |
| M-2a. 正常系・異常系・境界値のバランス | 3点 | **異常系が正常系の30%以上**あり、境界値テストがほぼ全メソッドに存在 |
| M-2b. モック・アサーションの適切さ | 3点 | `ArgumentCaptor` 等で引数の**内容**を検証（`verify()` のみは不可） |
| N-1. E2Eテストの機能網羅性 | 4点 | 全機能要件の90%以上をE2Eでカバー |
| N-2. E2Eテストケースの実効性 | 4点 | 異常系・権限テストあり + **形式的アサーション（`\|\| true`等）が0件** |
| O-1. テストの独立性・再現性 | 3点 | `@Transactional` ロールバック + テスト間依存なし + 順序非依存 |
| O-2. テストの可読性 | 2点 | メソッド名に条件と期待値 + AAAパターン一貫 |
| O-3. テスト仕様書との整合性 | 2点 | 仕様書のテストケースが全てコードとして実装済み |

---

## 採点の重要ルール（再現性の担保）

1. **全条件充足の原則** — 「全ての条件を満たす場合のみ満点」項目は1つでも欠けたら満点禁止
2. **疑わしい場合は低い点数** — 確認できない場合は高い点数を与えない
3. **根拠必須** — 全項目でファイル名・行番号・実際のコードを引用
4. **問題点は必ず報告** — セキュリティ問題・形式的テスト・重複コードを隠さない
5. **並列採点** — 4エージェントは同時起動（順次実行は禁止）

## 出力

### ファイル出力

採点完了後、対象フォルダに採点レポートが自動保存されます。

```
<対象フォルダ>/score-report_YYYYMMDD_HHMMSS.md
```

例: `C:/work/full-auto-dev/demo16/score-report_20260315_143022.md`

複数回採点しても上書きされず、タイムスタンプ付きで蓄積されます。

### レポートの構成

```
# SpringBoot3 Webアプリ 採点レポート
  対象フォルダ / 採点日時
─────────────────────────────
採点サマリー（表）
総合スコア・ランク
⚠️ 発見された問題点（セキュリティ/品質/テスト）
詳細採点結果（4カテゴリ × 全項目）
改善優先度テーブル（損失点数順）
```

### 画面表示（サマリー）

ファイル保存後、コンソールにスコアサマリーと問題点の概要が表示されます。

## 前提条件（対象フォルダの構成）

```
<アプリフォルダ>/
├── docs/
│   ├── requirements/       # 要件定義書（必須）
│   ├── design-basic/       # 基本設計書（必須）
│   ├── design-detail/      # 詳細設計書（必須）
│   ├── test-unit/          # 単体テスト仕様書（任意）
│   └── test-system/        # システムテスト仕様書（任意）
├── <springboot-project>/   # pom.xml を含むフォルダ
│   ├── src/main/java/
│   └── src/test/java/
└── e2e/tests/              # E2Eテスト（任意）
```

設計書・テスト仕様書が存在しない場合、該当項目は **0点** として処理されます。
