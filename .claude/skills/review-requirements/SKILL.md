要件定義書（`docs/requirements/`）に対して強化レビューを実施してください。

## 強化レビューの実施手順

**3つの独立したレビューエージェント**を git worktree で並行起動し、それぞれ異なる視点でレビューを実施してください。

### エージェント1：品質基準チェック

- 全 FR-ID に受け入れ条件が存在するか
  - 正常系（期待通りに動作する場合）の条件が記述されているか
  - 異常系（入力誤り・権限不足・上限超過・競合等）の条件が記述されているか
  - 受け入れ条件が「〜できること」「〜が表示されること」など検証可能な形式か
- 全 FR-ID に優先度（必須/推奨/任意）が定義されているか
- 非機能要件に具体的な数値目標が含まれているか（「高速」「十分な」等の曖昧表現がないか）
- トレーサビリティマトリクス（FR-ID × 画面 × API × TC-ID）が存在し、全 FR-ID が記載されているか

### エージェント2：ヒアリングシート充足チェック

- ヒアリングシートの全項目が要件定義書に反映されているか
- ヒアリング項目から FR-ID へのトレーサビリティが確保されているか
- ヒアリング内容の分割・統合・解釈が適切か（ヒアリング意図を損なっていないか）
- ヒアリングシートに記載された制約・前提条件が非機能要件または制約事項として定義されているか

### エージェント3：整合性・表記チェック

- 用語集に定義した表記が全ドキュメントで統一されているか（表記ゆれ・混在がないか）
- ドキュメント間の矛盾がないか（アクター・権限・機能の記述が一致しているか）
- 実装者が一意に解釈できない曖昧な表現がないか
- 権限マトリクス（ロール × 機能）の記号表記が統一されているか（「○」「×」等）
- 同一概念に複数の名称が使われていないか

## 集約・修正フロー

1. 3エージェントの指摘を集約し、重複・誤りを除去する
2. 全指摘を修正する（軽微な指摘も必ず対処する）
3. 修正後、さらに**新たな2エージェント**で再レビューを実施する
4. 指摘がなくなるまで繰り返す
5. 最終的なレビュー結果を要件定義のPRのdescriptionに記載する
