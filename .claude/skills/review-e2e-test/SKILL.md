E2Eテスト（仕様書・テストコード）に対して強化レビューを実施してください。

## 強化レビューの実施手順

**3つの独立したレビューエージェント**を git worktree で並行起動し、それぞれ異なる視点でレビューを実施してください。

### エージェント1：テスト仕様書・FR-ID カバレッジチェック

- `docs/test-spec/e2e/` にテスト仕様書が存在するか
- 要件定義書の全 FR-ID に対応する E2E テストシナリオが存在するか
- 以下の複合シナリオが含まれているか
  - 複数ロールが連携する業務フロー（例：一般ユーザーの申請 → 管理者の承認）
  - ステータス遷移を追うシナリオ（作成 → 処理中 → 完了・または却下）
  - 上限制約・ビジネスルール違反時のエラーシナリオ
  - 競合・排他制御が発生するシナリオ（楽観的ロック検証）
- 画面設計書（SCR*.md）の全ナビゲーションアクション（「〇〇リンク押下 → SCR00X へ遷移」）を網羅するシナリオが存在するか

### エージェント2：アサーション品質チェック

- 以下の禁止パターンが存在しないか確認する：
  ```bash
  grep -rn "toBeTruthy()\|toBeVisible.*body" src/e2e/ --include="*.ts" --include="*.js" 2>/dev/null
  grep -rn "if.*isVisible\|try.*click.*catch" src/e2e/ --include="*.ts" --include="*.js" 2>/dev/null
  ```
  - `toBeTruthy()` / `toBeVisible()` のみで内容を検証しない形式的アサーション
  - `if (isVisible)` 等の条件分岐で操作失敗を無視するフォールバックパス
- 業務ルール違反時のエラーメッセージを `toHaveText()` 等で具体的に検証しているか
- 操作後の画面状態変化（表示内容・ボタン活性状態・URL変化等）を具体的に検証しているか
- 画面状態遷移表（SCR*.md）の全状態に対するアサーションがあるか

### エージェント3：権限制御・環境設定チェック

- **権限制御テスト**
  - 未認証ユーザーが認証必須ページにアクセスした際のリダイレクトテストがあるか
  - 権限の低いロールが高権限専用ページにアクセスした際のアクセス拒否テストがあるか
  - 他ユーザーのリソースへの不正アクセスを試みるテストがあるか（あれば）

- **モック整合性**
  - テストで操作する画面のラベル・ボタン名・メッセージが承認済みモックおよび実装と一致しているか
  - ロケーター（`getByRole`・`getByLabel`・`getByText` 等）がモックの文言と一致しているか

- **Playwright 設定・エビデンス**
  - `screenshot: 'on'` が設定されており、テスト実行後にスクリーンショットが出力されるか
  - `playwright-report` が出力されるよう設定されているか
  - テスト実行コマンドが CI 環境でも動作するよう設定されているか

## 集約・修正フロー

1. 3エージェントの指摘を集約し、重複・誤りを除去する
2. 全指摘を修正する（軽微な指摘も必ず対処する）
3. 修正後、さらに**新たな2エージェント**で再レビューを実施する
4. 指摘がなくなるまで繰り返す
5. 最終的なレビュー結果をPRのdescriptionに記載する
