## 2. デザイン仕様（パターンB）

### 2.1 ナビゲーション構造
- SCR002 と同じドロワーメニュー構造
- アクティブメニュー: 「ユーザ管理」をハイライト（ADMINのみ表示）

### 2.2 カラー仕様
SCR002 と同様

### 2.3 コンポーネントスタイル

**ユーザ一覧テーブル**:
- PC: テーブル形式（ユーザID・名前・メールアドレス・ロール・操作ボタン）
- モバイル: カード形式
- ロールバッジ: ADMIN=プライマリカラー、USER=グレー
- 操作ボタン（各行）: 編集（アイコンボタン）、削除（赤アイコン）、PW再設定（鍵アイコン）

**ダイアログ（モーダル）**:
- 登録・編集ダイアログ: フォームを含むモーダル（最大幅 480px）
- 削除確認ダイアログ: 「本当に削除しますか？」確認テキストと確認/キャンセルボタン
- PW再設定ダイアログ: 新パスワード入力フォームのモーダル

### 2.4 空状態
- ユーザ0件: 「ユーザが登録されていません」と「ユーザを追加」ボタンを表示

### 2.5 ローディング状態
- テーブルスケルトンを表示

### 2.6 エラー状態
- API エラー: エラーメッセージとリロードボタン

## 5. アクション定義

| アクションID | 説明 | トリガー | APIエンドポイント | 動作 |
|------------|------|---------|----------------|------|
| A01 | ユーザ一覧読込 | ページ読込時 | GET /api/admin/users | ユーザ一覧を取得して表示する |
| A02 | 登録ダイアログ表示 | B13（ユーザ追加ボタン）押下 | なし | ユーザ登録ダイアログ（B17）を表示する |
| A03 | ユーザ登録 | 登録ダイアログの保存ボタン押下 | POST /api/admin/users | 入力内容を検証後、ユーザ登録 API を呼び出す。成功時はダイアログを閉じて一覧を再読込し、スナックバー表示 |
| A04 | 編集ダイアログ表示 | B14（編集ボタン）押下 | なし | 対象ユーザのデータをセットしてユーザ編集ダイアログ（B18）を表示する |
| A05 | ユーザ更新 | 編集ダイアログの保存ボタン押下 | PUT /api/admin/users/{id} | 入力内容と version を含めてユーザ更新 API を呼び出す。成功時はダイアログを閉じて一覧再読込。409 時はエラーメッセージ |
| A06 | 削除確認ダイアログ表示 | B15（削除ボタン）押下 | なし | 削除確認ダイアログ（B19）を表示する |
| A07 | ユーザ削除 | 削除確認ダイアログの確認ボタン押下 | DELETE /api/admin/users/{id} | 対象ユーザの version をリクエストに含めて削除 API を呼び出す。成功時はダイアログを閉じて一覧再読込。409 時はエラーメッセージ |
| A08 | PW再設定ダイアログ表示 | B16（PW再設定ボタン）押下 | なし | PW再設定ダイアログ（B20）を表示する |
| A09 | パスワード再設定 | PW再設定ダイアログの保存ボタン押下 | PUT /api/admin/users/{id}/password | 新パスワードをリクエストに含めてパスワード再設定 API を呼び出す。成功時はダイアログを閉じてスナックバー表示 |
| A10 | ページ切り替え | B21（ページネーション）押下 | GET /api/admin/users | 指定ページのユーザ一覧を取得する |
| A11 | アクティビティフィードへ遷移 | B03 押下 | なし（画面遷移） | SCR002 へ遷移する |
| A12 | ダッシュボードへ遷移 | B04 押下 | なし（画面遷移） | SCR003 へ遷移する |
| A13 | 図書一覧へ遷移 | B05 押下 | なし（画面遷移） | SCR004 へ遷移する |
